# Debts, credit cards, and loans

## Purpose

Treat a credit card or loan as an account the user can inspect and steer, while payments remain ordinary `D` (or `C`) lines in the PSV.

## What already works

- Bind payment with `D-CO` and extras `ACCOUNT|STARTING_BAL|APR`
- Second APR + change date
- Monthly interest before payment
- Running balance and paid-off flag
- Forecast debt summary
- Occurrence overrides

## What this increment adds

On the **expanded account/debt card**:

1. Current remaining balance (editable → writes STARTING_BAL / or a new B-like reset — prefer editing STARTING_BAL on the defining line plus a dated note; do not invent a shadow ledger)
2. APR (editable)
3. Payment strategy: min | fixed | pct
4. Pay URL (bookmark)
5. Notes
6. Category
7. Payment history (occurrences already generated by the engine)
8. Deterministic payoff projection
9. What-if slider for extra monthly payment
10. Due day + optional autopay flag
11. Labs chips (see `08-labs-mathjson.md`)

List view stays uniform. Debt chrome only appears when expanded (a tiny remaining-balance hint on the collapsed card is allowed).

## Strategy and engine

Interest stays: `(APR / 100 / 12) * runningBal` on each payment date before applying the payment.

Payment amount used by the engine:

- `fixed`: line AMOUNT, in dollars
- `min`: `max(floor, minRate * runningBal)`. Default `minRate` is 0.10. A per-account override is the MIN_RATE extra (`0.02` = 2%). Floor is the line AMOUNT when filled; otherwise $0.01
- `pct`: AMOUNT is a percent of the remaining debt balance. `5` pays `0.05 × runningBal`. Not a percent of income, and not a dollar amount

What-if slider does **not** write the file until the user clicks “Apply extra to this account”. Live math is preview only. Applying writes `extraPayment` on the account (field already exists on `Account`) and/or adjusts AMOUNT — prefer `extraPayment` so the scheduled AMOUNT stays the contractual payment.

## Payoff projection (deterministic)

Inputs: runningBal, APR, strategy-resolved payment, extraPayment, forecast window (settings months).

Outputs shown on the card:

- Months to payoff (or “beyond forecast window”)
- Estimated total interest in window
- Estimated payoff date
- Disclaimer: monthly simple APR/12, not the lender’s method

Do this in TypeScript. Do not call the LLM for the primary number.

## What-if slider

- Range: $0 extra to a sane cap (e.g. min(runningBal, 2× current payment) or user-typed).
- Immediate recalculation of payoff date and interest saved vs baseline.
- “Apply” persists extraPayment.

## Pay URL

- Text field + “Open” button.
- Opens the URL only. No scraping, no login automation.

## Autopay and due day

- Due day: derived from WHEN day-of-month when frequency is monthly; otherwise show next occurrence date.
- Autopay: boolean metadata. **v1 storage:** encode in NOTES as a structured prefix only if we cannot add a field without breaking extras order — **preferred:** add optional `AUTOPAY` as `Y`/`N` after NOTES is too messy.  

**Locked for v1:** store autopay as a boolean on the Account object in memory, serialize as extra token `autopay` or `noautopay` in the extras list after STRATEGY if present. If absent, false.

Example:

```
D-CO|2026-04-15,R|150|Capital One-4321|CO|2800|19.99|fixed|https://www.capitalone.com|debt|call to dispute fee|autopay
```

If this extra collides with parser extras indexing, update extras parsing to **named** extras after APR rather than positional-only. That is part of Slice 0.

## Payment history

List generated occurrences for this accountId inside the forecast window: date, amount, interest that month, remaining after payment, override/pending flags. Read-only in v1 except “edit this occurrence” which writes `|#N=`.

## Import from spreadsheets (later, but design now)

User pastes TSV/CSV. Mapping UI: column → field (name, last4, balance, APR, payment, due, url). Generate PSV lines. Unmapped category → Unfiled. Not required to ship before dual-mode.
